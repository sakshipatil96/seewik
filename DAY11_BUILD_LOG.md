# Day 11 Build Log — Initiative attendance and corrected rewards

Date: 2026-08-30

## Outcome

Day 11 is implemented and deployed. Seewik now supports two explicitly different Initiative attendance records:

- organiser-code attendance during the scheduled three-hour window, worth 20 points once per joined participant; and
- self-attested attendance after the code window closes, available for seven days after completion and worth zero points.

The organiser receives 40 points exactly once only when the Initiative is completed and two distinct joined participants have used the organiser code. The threshold is correct whether completion or the second attendance occurs first.

The contribution policy is frozen as 5 points for a first accepted filing, 20 for organiser-code attendance, 40 for eligible completed organising and 60 for a first verified civic fix. Existing ledger records were not rewritten.

## Implemented integrity boundaries

- Codes are six digits, generated by the server with HMAC-SHA256, bound to one Initiative and ten-minute slot.
- The preceding code is accepted only for the first two minutes of the new slot and never beyond `startAt + 3 hours`.
- Incorrect entries are limited to five per participant, Initiative and slot.
- Submitted plaintext codes are not stored or logged; attempt records contain only hashes, slot, count, schema and server time.
- Attendance mutations require the caller's own `PARTICIPANT` record and a Google-linked Firebase identity at the controller boundary.
- Attendance events, zero/non-zero ledger entries and organiser awards are transactional, append-only and idempotent.
- Self-attendance cannot be silently upgraded to code attendance.
- Cancellation is rejected after the first organiser-code attendance.
- Joiners and attendance counts derive from `PARTICIPANT` records and exclude the organiser.
- Direct Firestore client access to Initiatives, Initiative events, participations and attendance attempts is denied.

## Interface behavior

- `My activities` displays separate organiser-code and self-reported counts with no independent-verification claim.
- During the code window, participants see numeric six-digit entry and organisers can reveal the rotating code.
- After the code window, eligible completed participants see `I attended · 0 points`.
- English, Marathi and Hindi copy covers display, entry, expiry, rate-limit, success and reward disclosures.
- Input uses the mobile numeric keyboard, one-time-code autocomplete, a six-character limit, accessible labels and status announcements.
- Points UI displays the exact 5/20/40/60/0 policy.
